# Firebird — умный подбор подрядчиков

Работающий локальный прототип по краткому описанию кейса HackAlem AI. Заказчик выбирает город, дату, формат, категорию и бюджет на одну услугу; сервис возвращает до трёх карточек из готового каталога с объяснениями.

## Запуск

Откройте `dist/index.html` в современном браузере. Установка, интернет, аккаунты и API-ключи не требуются. Все файлы папки `dist` должны оставаться рядом.

Для запуска через HTTP при установленном Python: из папки проекта выполните `python -m http.server 4173 --bind 127.0.0.1 --directory dist` и откройте `http://127.0.0.1:4173`.

## Что реализовано

- Русскоязычная адаптивная форма: три города, четыре категории, четыре формата, дата и бюджет в тенге.
- Проверка города, категории, формата, календаря занятости и фиксированной полной цены пакета.
- До трёх результатов, ранжированных по числу мероприятий выбранного формата, затем по цене и стабильному ID.
- Фактические объяснения и карточка состава пакета, открываемая кнопкой.
- Отдельный сценарий отсутствия совпадений и объяснение исключений.
- Защита от пустых и некорректных входных данных. Неизвестная цена или доступность не считаются совпадением.
- Пометка устаревших результатов после изменения параметров до повторного поиска.
- Необязательный WebMCP-инструмент для поддерживающих браузеров, использующий те же функции, что и форма.

## Данные и ограничения

Все 48 записей — вымышленные демонстрационные данные: имена, услуги, цены, опыт и календарь. Доступность задана в диапазоне 2026-01-01 — 2027-12-31, занятые даты явно перечислены; за пределами диапазона доступность считается неизвестной. Формат каталога описан в `dist/catalog.js`.

Реальный каталог Firebird, полное ТЗ, критерии оценки и репозиторий команды не предоставлены. Соответствие неизвестным требованиям не подтверждено.

Внешняя AI-модель не подключена. Рекомендации и объяснения работают на прозрачных правилах. AI-агент использован при разработке. Персональные данные, секреты и внешние интеграции не используются. Нет бронирования, оплаты, контактов и постоянного хранения. Сайт не опубликован; это локальный прототип.

Бюджет относится к одному указанному пакету, а не ко всему мероприятию. Данные о гостях, продолжительности сверх пакета, доставке и дополнительном оборудовании не входят в запрос. Не следует считать демо-цену реальной сметой.

## Архитектура

Статический HTML, CSS и JavaScript без сторонних библиотек. `catalog.js` содержит записи; `matcher.js` валидирует запрос, фильтрует и ранжирует; `app.js` управляет формой и карточками. Каталог загружается локально, сетевых запросов нет. Перед подключением реального каталога нужен адаптер к его структуре и проверка полноты данных; для вызовов AI с секретным ключом потребуется сервер.

## Проверка основного сценария

1. Выберите Алматы, 2026-09-30, корпоратив, ведущего, бюджет 250 000 ₸. Ожидаются Арман Серик (180 000 ₸) и Дана Алиева (220 000 ₸). Тимур исключён по формату, Айша — по неизвестной доступности.
2. Нажмите «Что входит в стоимость»: появятся состав пакета, причины и ID источника. Закройте окно клавишей Escape.
3. Уменьшите бюджет до 100 000 ₸ и повторите поиск: результатов нет, минимальная подходящая стоимость — 180 000 ₸.
4. При бюджете 250 000 ₸ измените дату на 2026-10-10: Арман занят; остаётся Дана.
5. Выберите дату за пределами 2026–2027 годов: подтверждённых результатов нет.
6. Выберите свадьбу и бюджет 400 000 ₸: три карточки.

При установленном Node.js: `node tests/matcher.test.cjs`. Проверяются границы бюджета, занятые даты, неизвестные данные, валидация, ограничение числа результатов и соответствие всех возвращённых записей фильтрам.

## Следующие шаги для реального кейса

Подключить предоставленный Firebird каталог; сверить обязательные функции с полным ТЗ; при необходимости добавить серверную AI-интеграцию. Для сдачи разместить итоговую версию в выданном командном репозитории и оформить решение на платформе хакатона. Эти действия в прототипе не выполнялись.
