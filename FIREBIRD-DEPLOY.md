# Развёртывание Firebird

Сервер подготовлен, но публичный хостинг ещё не подключён. GitHub Pages запускает только интерфейс и подбор: он не хранит аккаунты, фото, отзывы и услуги. Для общей базы нужен отдельный сервер с постоянным диском.

## Вариант: Render Web Service

Создание платного сервиса выполняйте после проверки цены в Render. Бесплатный сервис с временным диском не подходит для постоянной SQLite-базы.

1. Войдите в https://dashboard.render.com и создайте **New → Web Service**.
2. Подключите репозиторий `imfrqte/Rampage`, ветку `main`. Выберите runtime **Python 3**.
3. Build Command:
   ```sh
   python -m zipfile -e Firebird-server-project.zip . && pip install -r firebird/requirements.txt
   ```
4. Start Command:
   ```sh
   gunicorn --chdir firebird --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 60 server.app:application
   ```
5. Выберите платный экземпляр с поддержкой persistent disk. Добавьте диск размером 1 GB с Mount Path `/var/data`.
6. В Environment задайте `FIREBIRD_DB=/var/data/firebird.sqlite3`. `RENDER_EXTERNAL_URL` Render задаёт автоматически; сервер использует этот адрес для проверки источника запросов. Для собственного домена задайте `PUBLIC_ORIGIN=https://ваш-домен` без пути.
7. Health Check Path: `/api/health`. Число экземпляров: один. SQLite рассчитана на один сервер с диском, не на горизонтальное масштабирование.
8. После запуска откройте HTTPS-адрес Render. Зарегистрируйте два тестовых аккаунта, опубликуйте услугу, проверьте её из другого аккаунта, сохраните избранное, загрузите фото и оставьте отзыв. После перезапуска сервиса проверьте сохранность данных.
9. Используйте адрес Render как основной адрес продукта. На GitHub Pages остаётся автономная демонстрация. Фронтенд и API должны работать на одном origin.

Документация: https://render.com/docs/deploy-flask (настройка Python/WSGI), https://render.com/docs/disks, актуальные цены https://render.com/pricing. Платный сервис не создавался и оплата не выполнялась.

## Подключение AI

В переменные окружения **сервера**, не в GitHub-файлы и не в чат, добавьте:

- `OPENAI_API_KEY`: ваш ключ проекта OpenAI с доступом к Responses API.
- `OPENAI_MODEL=gpt-4.1-mini` (можно заменить совместимой моделью со Structured Outputs).
- `OPENAI_DAILY_REQUEST_LIMIT=100`: общий лимит запросов в сутки, дополнительно 30 на аккаунт. Неуспешные попытки тоже учитываются. Это лимит количества, а не денежный бюджет; бюджет проекта настройте отдельно в OpenAI.

Перезапустите сервер. В помощнике появится статус подключения. Без ключа работает только встроенная справка. Подписка ChatGPT сама по себе не настраивает API-биллинг проекта.

Проверочный запрос: «Нужен ведущий в Алматы на корпоратив 6 октября 2026, бюджет 500000 тенге». Проверьте предложенные параметры и нажмите «Применить и подобрать». ИИ не создаёт подрядчиков, не меняет каталог и не бронирует услуги. История хранится в памяти вкладки; последние 8 сообщений и текущие параметры передаются OpenAI. Запрос использует `store:false`, что не является обещанием нулевого хранения провайдером. Живой вызов OpenAI пока не проверен: ключ не предоставлен. Серверные ветки проверены с подменённым ответом API.

Документация: https://developers.openai.com/api/docs/guides/structured-outputs

## Геолокация

Работает на HTTPS и localhost, только по запросу пользователя и после разрешения браузера. Используется `getCurrentPosition`, постоянного слежения нет. BigDataCloud получает текущие координаты и IP напрямую из браузера. Firebird координаты не сохраняет; пользователь подтверждает город перед применением. Сервису нельзя отправлять сохранённые, чужие или искусственные координаты. Отказ, таймаут, неточный результат и неизвестный город оставляют ручной выбор доступным. Точных адресов подрядчиков нет, поэтому сортировки по расстоянию нет.

Документация и условия: https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api и https://www.bigdatacloud.com/docs/article/fair-use-policy-for-free-client-side-reverse-geocoding-api

## Данные и эксплуатация

В SQLite находятся аккаунты, хеши паролей, сессии, фото, услуги, избранное, запросы и отзывы. Базу и резервные копии нельзя добавлять в публичный GitHub. ZIP исключает `.runtime`, файлы SQLite и `.env`; рабочая база не распространяется.

Для резервной копии используйте SQLite backup API при работающем сервере, а не простое копирование одного файла в режиме WAL. Храните копии в приватном хранилище и проверяйте восстановление. До массового публичного запуска нужны подтверждение email, восстановление пароля, модерация и жалобы на отзывы/услуги, административные инструменты и политика обработки данных. Сейчас отзыв означает мнение аккаунта, а не подтверждённую покупку.

Для Docker: распакуйте ZIP, выполните `docker build -t firebird .` внутри `firebird`; примонтируйте приватный persistent volume к `/data`, установите `PUBLIC_ORIGIN`, публикуйте через HTTPS-прокси. Docker/Gunicorn подготовлены, но в текущей Windows-среде не запускались. Локальные проверки выполнены на Python WSGI-сервере.
