# Firebird — умный подбор подрядчиков (#79-lite)

Сервис помогает заказчику выбрать до трёх event-подрядчиков из предоставленного каталога. Каждая карточка объясняет совпадение с запросом и приводит конкретный фрагмент описания профиля. Занятые на дату подрядчики не попадают в выдачу.

**Открыть сайт:** https://imfrqte.github.io/Rampage/Firebird-server.html  
**Репозиторий команды:** https://github.com/imfrqte/Rampage

## Быстрый запуск

Для полного режима распакуйте `Firebird-server-project.zip`, перейдите в папку `firebird` и выполните:

```sh
python -m pip install -r requirements.txt
python server/app.py
```

Откройте http://127.0.0.1:4180. Нужен Python 3.12+. Это локальный сервер разработки; для общего доступа используйте HTTPS и Gunicorn. Инструкция — `firebird/DEPLOY.md` внутри архива или `FIREBIRD-DEPLOY.md` в корне репозитория.

Автономный `Firebird-server.html` и GitHub Pages поддерживают подбор из каталога. Аккаунты, общие услуги, отзывы, фото и избранное требуют сервер. AI дополнительно требует серверный `OPENAI_API_KEY`; без ключа доступна справка. Геолокация требует HTTPS/localhost, разрешения пользователя и доступа к BigDataCloud.

Пересборка и проверки:

```sh
python scripts/build.py
node tests/matcher.test.cjs
node tests/location.test.cjs
node tests/location-flow.test.cjs
python tests/server_test.py
```

Сборщик создаёт автономный HTML, README и ZIP рядом с папкой проекта. Рабочая база и ключи в архив не входят.

## Что реализовано

- Все 66 профилей, 17 категорий и 6 форматов исходного датасета; справочник 90 городов Казахстана плюс исходное значение «Зарубежье». Наличие города в форме не означает наличие подрядчиков в каталоге.
- Регистрация по email и паролю, личный кабинет, публикация/редактирование собственных услуг, черновики и архив. Пользовательская витрина отделена от 66 исходных профилей.
- Избранные подрядчики отдельной вкладкой и сохранённые запросы.
- Фото профиля: JPG/PNG/WebP до 5 МБ и 16 Мп, квадрат 400×400, удаление метаданных, замена и удаление фото.
- Отзывы с оценкой 1–5, средней оценкой и количеством. Один отзыв аккаунта на карточку, изменение и удаление только своего; запрет отзывов на собственные услуги. Отзывы не подтверждают покупку и не влияют на детерминированный подбор.
- AI-помощник: свободный текст → уточнения → проверенные параметры → явное применение пользователем. Интеграция Responses API подготовлена; без ключа модель не работает.
- «Определить мой город»: разовое определение через браузер и BigDataCloud, подтверждение города перед применением, обработка отказа и ошибок. Никакого фонового отслеживания или выдуманного расстояния до подрядчика.
- Обязательные входы: город, дата, формат, категория, бюджет в тенге за мероприятие. Опциональные: язык и длительность присутствия.
- До трёх карточек с именем, категорией, городом, ценой «от» и объяснением на основании полей и дословного фрагмента описания.
- Три явных исхода: `matched` — подобрали; `no_category` — в городе нет этой категории; `no_matches` — категория есть, но никто не прошёл все условия.
- Если карточек меньше трёх, указано количество исходных кандидатов и причины исключения. У профиля может быть несколько причин; их счётчики не нужно складывать.
- Площадки и люди проходят один и тот же фильтр занятости. Поиск по любой категории из списка профиля поддерживается.
- После смены только даты показано, кто из прежней подборки теперь занят и кто из новой был занят раньше.
- Цены и города, заполненные при подготовке датасета, отмечены отдельно. Синтетические профили организаторов отличимы от остальных анонимизированных профилей.
- Пять кнопок демонстрационных запросов, подробный профиль с источником, адаптивная форма и необязательный WebMCP-инструмент для поддерживающих браузеров.

## Как устроено решение

1. **Валидация.** Проверяем значения справочников, дату, бюджет, язык и длительность. Календарь известен только с 23.09.2026 по 31.12.2026 включительно; вне этого окна выдаём понятную ошибку, не предполагаем свободные даты.
2. **Город и категория.** Сначала формируем исходный список. Пустой список означает отдельный исход `no_category`, независимо от других фильтров.
3. **Жёсткие фильтры.** Исключаем занятых (`busy_dates`), неподдерживаемый формат, начальную цену выше бюджета, неподдерживаемый язык, недостаточный `max_hours`. Пустая начальная цена не принимается за ноль. `max_hours = null` означает работу без привязки к присутствию, поэтому фильтр длительности не применяется.
4. **Детерминированное ранжирование.** Считаем число различных тематических основ слов в описании для выбранного формата. Например, для корпоратива: `корпоратив`, `бизнес`, `делов`, `бренд`, `компан`, `тимбил`. При равенстве сначала идут записи без `price_imputed`, затем без `city_imputed`, затем с меньшей начальной ценой и меньшим лексикографическим ID. `synthetic` не влияет на порядок.
5. **Объяснение.** В карточке отдельно показаны совпадения по полям, статус календаря и дословный фрагмент описания. В подробном профиле доступно полное текстовое объяснение. Выбор фрагмента учитывает формат, слова об услуге и редкость слов в корпусе; приветствия и перечисления клиентов штрафуются. Это извлечение текста, не генерация новых фактов. Полный исходный текст и ID доступны в карточке.
6. **Выдача.** Берём первые три записи. Объясняем недостаток вариантов и сохраняем проверяемые причины исключения остальных.

Одинаковый запрос возвращает одинаковые ID, порядок и объяснения. Время, случайные числа и сетевые ответы не участвуют в расчёте. Числовой балл — прозрачная эвристика, не вероятность качества подрядчика.

## Архитектура и технологии

HTML/CSS/JavaScript без клиентских библиотек; сервер Python WSGI + SQLite, Pillow для фото и Gunicorn для production. AI-агент использовался при разработке; основной подбор детерминированный. Необязательный помощник использует OpenAI Responses API со строгой JSON-схемой, а ответ повторно валидируется на сервере.

Пароли: PBKDF2-SHA256 с солью; сессии: случайные токены, в базе только хеш, HttpOnly/SameSite=Lax и Secure при HTTPS. Мутации проверяют Origin и специальный заголовок, права владельца и ограничения входных данных. Есть лимиты запросов. Полноценный аудит безопасности не проводился.

```text
data/contractors.csv → scripts/build.py → dist/catalog.js
Форма → matcher.validate → фильтры → ранжирование → объяснения → app.js → карточки
```

- `dist/index.html`, `dist/styles.css` — интерфейс.
- `dist/catalog.js` — типизированные поля CSV и происхождение данных (включая SHA-256).
- `dist/matcher.js` — фильтрация, ранжирование, объяснения и сравнение дат; используется и браузером, и тестами.
- `dist/app.js` — форма, карточки, состояния, примеры, диалог профиля и WebMCP.
- `tests/matcher.test.cjs` — проверки обязательных сценариев и независимый фильтр для сверки.
- `scripts/build.py` — воспроизводимая сборка стандартной библиотекой Python.

## Данные и смысл цены

Источник — предоставленный участником `hackathon dataset anonymized .csv`, сохранён без изменения байтов в `data/contractors.csv`. HTML-превью использовалось только как справочный материал; основным источником служит CSV. JSONL не предоставлялся.

В датасете 66 записей: 53 анонимизированных несинтетических профиля и 13 синтетических профилей организаторов. Город заполнен при подготовке в 8 записях, цена — в 18. Собственные синтетические профили не добавлены. Имена вымышленные. У одного подрядчика может быть несколько категорий, поэтому сумма численности категорий превышает 66.

`price_from_kzt` — цена **от** за мероприятие, не фиксированная смета и не почасовая ставка. Проверка `price_from_kzt <= budget` означает только прохождение фильтра начальной цены. Не обещаем экономию, фиксированный пакет или окончательную стоимость. Цена не умножается на часы.

`busy_dates` полностью определяет календарь в указанном 100-дневном окне. Отсутствие даты в списке означает «не занят по календарю датасета», а не подтверждение от реального подрядчика.

## Проверки

`node tests/matcher.test.cjs` проверяет три исхода, календарные границы, цену на границе бюджета, язык, часы и `null`, занятость площадок, повторяемость, независимость от порядка строк и извлечение фрагментов строго из источника. Дополнительно проверяются 1 224 сочетания города, категории, формата и даты независимым фильтром и занятая дата каждого из 66 профилей. Скрипт выводит измеренное время поиска в локальном Node.js; это не гарантия производительности любого браузера.

## Ограничения и развитие

Нет бронирования, заявок, уведомлений, оплаты и проверки сведений у подрядчиков. Поиск работает только по предоставленному каталогу и календарю. Свободный текст не переопределяет структурированные город, формат, язык, цену или занятость. Лексическая эвристика может пропускать синонимы и не понимает отрицания как полноценная языковая модель.

Для публичной работы новых функций нужен сервер с постоянным диском. Хостинг и ключ OpenAI ещё не подключены. Нет подтверждения email, восстановления пароля и модерации отзывов/услуг. Подготовка к развёртыванию описана в DEPLOY.md. Серверные тесты проверяют аккаунты, права, CSRF, фото, отзывы и AI с имитацией внешнего API. Живая геолокация устройства и живой запрос модели не проверялись. Автоматическая отправка решения на платформу хакатона не выполнялась.
